# 图生图原图尺寸设计

## 目标

在 Web 端图生图模式中，新增一个仅对单张参考图显示的“原图尺寸”画布比例选项。该选项沿用参考图宽高比，不沿用参考图真实像素尺寸。提交时仍向后端发送 `size` 字符串，并继续遵循现有 `1K`、`2K`、`4K` 质量档位。

## 范围

本次调整仅覆盖 `web` 端图生图页面与对应请求组装逻辑，限制条件如下：

1. 仅在图生图模式显示。
2. 仅在参考图数量等于 1 时显示。
3. 文生图保持现状。
4. 多参考图图生图保持现有固定比例列表。

## 现状

当前画布比例由 `web/src/features/image/options.ts` 提供静态比例列表，`resolveOutputSize` 只接受固定 `AspectRatio` 联合类型并返回预设尺寸。图生图参考图 `SourceImage` 结构中没有宽高元数据，因此界面无法基于上传图片生成动态比例项。

当前图生图请求仍通过 `size` 字段提交目标输出尺寸，服务端会根据 `size` 推导宽高比前缀，并根据 `size` 识别计费档位。

## 方案

### 参考图元数据

为 `SourceImage` 增加原图宽高字段。上传普通图片或 HEIC 转换结果后，读取可提交文件的实际宽高并写入状态，供界面展示与尺寸换算使用。

读取逻辑使用浏览器图片解码能力，通过 `blob:` 预览地址或 `FileReader` 数据读取生成 `Image` 对象，成功后记录 `width`、`height`。如果宽高读取失败，则保留现有比例列表，避免阻塞上传。

### 比例选项展示

图生图比例区在静态列表前动态插入“原图尺寸”卡片，显示条件为：

1. `mode === 'img'`
2. `sourceImages.length === 1`
3. 单张参考图存在有效 `width` 与 `height`

该卡片文案显示为：

1. 主文案：`原图尺寸`
2. 次文案：`{width}:{height}` 的最简比例，例如 `1170:2532` 会显示为 `195:422`
3. 说明文案：`沿用参考图比例`

当参考图数量从 1 变为 0 或大于 1 时，如果当前选中的就是“原图尺寸”，则自动回退到 `1:1`，避免界面保留失效状态。

### 动态尺寸换算

“原图尺寸”对应的提交语义是“沿用原图比例”。因此仍需按照现有质量档位生成目标像素尺寸：

1. 取质量档位对应的基准像素面积，沿用当前各档位的大致像素规模。
2. 根据原图宽高比计算输出宽高。
3. 输出宽高使用整数像素，并尽量保持与原图宽高比一致。
4. 如果宽高读取失败，则回退到静态 `1:1`。

为了保持服务端计费识别稳定，本次将动态输出尺寸限制在现有计费表可识别的三个面积档位附近：

1. `1K` 以约 1024×1024 面积为基准。
2. `2K` 以约 2048×2048 面积为基准。
3. `4K` 以约 2880×2880 面积为基准。

动态尺寸不会强制套入既有固定比例表，因此需要同步扩展服务端计费尺寸识别逻辑：当 `size` 未命中静态映射时，按像素面积区间归类到 `1K`、`2K`、`4K`。

### 请求组装

`editImage` 增加可选 `size` 覆盖参数。

1. 如果界面选择的是静态比例，继续按 `aspectRatio + quality` 走现有 `resolveOutputSize`。
2. 如果界面选择的是“原图尺寸”，优先发送前端计算出的动态 `size`。
3. 本地账号池与外置图片渠道沿用现有 `shouldSendOutputSize` 规则。

## 错误处理

1. 图片上传成功但宽高读取失败：仍保留参考图，比例区隐藏“原图尺寸”卡片。
2. 单图切换为多图：自动取消“原图尺寸”选中态并回退到 `1:1`。
3. 删除唯一参考图：同样回退到 `1:1`。

## 测试

需要覆盖以下场景：

1. 单张图生图上传后显示“原图尺寸”卡片。
2. 选择“原图尺寸”后提交时，`editImage` 收到动态 `size`。
3. 多图图生图时隐藏“原图尺寸”卡片。
4. `editImage` 在收到 `size` 覆盖参数时优先发送该值。
5. 计费质量识别在动态尺寸下仍能归类到正确档位。
